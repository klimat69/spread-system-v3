# Терминал MEXC — инструкция (v3.1.18)

Кратко: **Paper** = симуляция по стакану и ленте MEXC, без ордеров на бирже. **Live** = реальные лимитные ордера (нужны ключи и валидация).

---

## Шапка

| Надпись | Что это |
|---------|---------|
| **WS подключён** | Окно приложения связано с backend на этом Mac. Это не статус биржи. |
| **Поток: OK** | С MEXC приходят стакан и сделки. **Без OK бот не торгует.** |
| **Поток: Проблема** | Поток не готов (прогрев, обрыв, пустой стакан, долгая тишина ленты). |
| **Автоторговля** | Разрешить анализ рынка и сделки (Paper или Live). |
| **Старт / Стоп** | Включить / выключить движок (`TradingEngine`). |

---

## Рынки (слева)

- **Спот** — пара вида `BTC/USDT`.
- **Фьючерсы (swap)** — пара вида `BTC/USDT:USDT` (перпетуал USDT-M).
- Поиск и **Популярные** — быстрый выбор символа.
- После смены пары нажмите **Сохранить конфиг**, затем **Старт**.

---

## Центр: графики и метрики

| Элемент | Назначение |
|---------|------------|
| **Линия mid** (Paper) | Средняя цена стакана `(bid+ask)/2` в реальном времени. |
| **Маркеры ▲▼** | Вход (яркие) и выход (бледные) симулированных сделок Paper. |
| **TradingView внизу** | Только обзор; бот **не** торгует по этому графику. |
| **1 сек / 5 сек / 1 мин** | Интервал виджета TV, не логика бота. |
| **Задержка потока MEXC → экран** | Свежесть данных бота (обычно сотни мс). |
| **Спред / Дисбаланс** | Текущие значения для сигналов (см. «Скальп»). |

---

## Справа: «Аналитика Paper»

Таблица вход / выход / P/L по **симуляции**, не по счёту MEXC.

- **Вход:** buy @ bid, sell @ ask (как в коде `engine.py`).
- **Выход:** long закрывается @ bid, short @ ask.
- P/L считается от этих цен и **размера ордера** из настроек.

---

## Что реально влияет на сигналы (важно)

Сейчас торговый движок использует **`SimpleScalpEngine`** (`backend/app/simple_scalp.py`), а не полный класс `StrategyEngine` из `strategy.py`.

| Блок в UI | Paper (демо) | Live |
|-----------|--------------|------|
| **Скальп** (`spread_min`, `imbalance_min`, `aggression_min`) | **Да** — вход/выход | **Да** |
| **Мягкие сигналы (демо)** | **Да** — поток OK при прогреве ленты/sequence | Нет |
| **Размер ордера** | **Да** — размер симуляции | **Да** |
| **Стратегия** (удержание, cooldown, пороги входа/выхода в UI) | **Нет** для сигналов* | Частично** |
| **Скальп:** stale / replace bps | Нет | **Да** — отмена/перестановка лимитки |
| **Риск** | Нет | **Да** — блокировка входа |
| **Стратегия → устаревание потока** (`market_data_stale_after_seconds` и др.) | **Да** — статус «Поток» | **Да** |

\*Поля «Макс. удержание», «Пауза между входами», «Выход по дисбалансу», «Порог агрессии входа» в интерфейсе **сохраняются в config**, но **не читаются** `SimpleScalpEngine` при Paper/Live в текущей версии.

\*\*«Макс. открытых ордеров» действует только в **Live** при выставлении ордера.

### Логика «Скальп» (как бот думает)

На каждом тике стакана:

1. **Спред** — относительный `(ask−bid)/mid`, должен быть ≥ `spread_min`.
2. **Дисбаланс стакана** — `|imbalance| ≥ imbalance_min`; для **buy** нужен положительный дисбаланс, для **sell** — отрицательный.
3. **Агрессия ленты** — по последним ~60 сделкам: `(покупки−продажи)/объём`; `|aggression| ≥ aggression_min`, знак согласован с стороной.
4. **Вход** — был «flat», все три условия выполнились → открыть buy или sell.
5. **Выход** — сигнал пропал или сменилась сторона → закрыть позицию в Paper или отменить/перевыставить в Live.

## Настройки → Подключение

| Поле | Paper | Live |
|------|-------|------|
| API ключ / секрет | Не обязательны | Обязательны |
| Режим Paper / Live | Выбор режима | |
| Разрешить live-ордера | — | Доп. флаг безопасности |
| **Мягкие сигналы (демо)** | При прогреве потока (`RECOVERING`, `tape_warming_up` / `sequence_warming_up`) разрешает торговлю, если bid/ask уже есть | — |
| **Размер ордера** | Объём симуляции (например `0.001` BTC) | Размер лимитки |

---

## Скальп — поля

| Поле | Смысл | Типичный масштаб (BTC) |
|------|--------|-------------------------|
| **Мин. спред** | Минимальный относительный спред bid/ask | `0.0002` ≈ 2 bps |
| **Мин. дисбаланс** | Перевес объёма в стакане (0…1) | `0.12`–`0.30` |
| **Мин. агрессия ленты** | Перевес агрессивных покупок/продаж в ленте (0…1) | `0.08`–`0.25` |
| **Отмена устаревшего ордера** | Live: отменить лимитку через N сек | ~`1.5` |
| **Перестановка при сдвиге (bps)** | Live: переставить, если цена ушла | ~`3` |

---

## Стратегия — поля в UI

| Поле | Задумка | Сейчас в коде |
|------|---------|----------------|
| Макс. удержание (сек) | Тайм-аут позиции | Метод есть, **в цикл торговли не подключён** |
| Макс. открытых ордеров | Лимит лимиток | **Только Live** |
| Пауза между входами | Cooldown | **Не используется** |
| Выход по дисбалансу | Выход при выравнивании стакана | **Не используется** (есть в `StrategyEngine`, но движок его не вызывает) |
| Порог агрессии входа | Сила ленты для входа | **Не используется** (вместо него `aggression_min` в Скальп) |
| Устаревание стакана (сек) | Поток «Проблема», если стакан старый | **Да** — `market_data.py` |

Другие пороги из `config.strategy` (тишина WebSocket, лента, задержка событий, глубина стакана) влияют на **здоровье потока**, не на формулу входа Paper.

---

## Риск — только Live

| Поле | Действие |
|------|----------|
| Макс. дневной убыток | Стоп при P/L за день ≤ −лимит |
| Макс. размер позиции | Одна заявка не больше лимита |
| Макс. экспозиция | Лимит `(позиция + заявка) × цена` |
| Пауза после убытка | Блок входов после минусовой сделки |

В **Paper** риск-лимиты **не проверяются**.

## Три шаблона для BTC/USDT (фьючерс)

Сохраните конфиг после правок. Режим: **Paper**, **Фьючерсы**, символ **`BTC/USDT:USDT`**, **Старт** + **Автоторговля**.

### 1. Спокойный (мало сделок, строже фильтры)

| Параметр | Значение |
|----------|----------|
| Мин. спред | `0.00028` |
| Мин. дисбаланс | `0.26` |
| Мин. агрессия | `0.22` |
| Размер ордера | `0.001` |
| Мягкие сигналы | выкл |

Ожидание: редкие входы, меньше шума.

### 2. Базовый (заводские настройки)

| Параметр | Значение |
|----------|----------|
| Мин. спред | `0.0002` |
| Мин. дисбаланс | `0.2` |
| Мин. агрессия | `0.15` |
| Размер ордера | `0.001` |

Баланс между частотой и качеством сигналов.

### 3. Активный (больше сделок для теста UI)

| Параметр | Значение |
|----------|----------|
| Мин. спред | `0.00012` |
| Мин. дисбаланс | `0.12` |
| Мин. агрессия | `0.08` |
| Мягкие сигналы | **вкл** |
| Устаревание стакана | `3` (сек) — чуть мягче поток при прогреве |

Ожидание: чаще сигналы; P/L в Paper более «шумный», для отладки интерфейса.

**Отличия шаблонов:** все три меняют только блок **Скальп** (+ «Мягкие сигналы» в активном). Блоки **Стратегия** и **Риск** для Paper-сигналов не меняют поведение (кроме «Устаревание стакана» для статуса потока).

## Paper — чеклист

1. Режим **Paper**.
2. **Сохранить конфиг** → **Старт** → **Автоторговля**.
3. **Поток: OK**, bid/ask ≠ 0.
4. Смотреть **график mid**, **Аналитика Paper** справа.
5. API ключи не нужны.

Если сделок нет: уменьшите пороги в **Скальп** или включите **Мягкие сигналы**; подождите 15–30 с после старта.

## Установка и обновления

### Intel Mac (ручная сборка)

Файл на рабочем столе: **`Spread-System-v3-3.1.18-Intel-Mac.dmg`** (backend `x86_64`).

Установка: открыть DMG → перетащить в «Программы». Если macOS блокирует — ПКМ → «Открыть».

**Apple Silicon (M1/M2/M3):** нужен `spread-system-v3-arm64.dmg` из [Releases](https://github.com/klimat69/spread-system-v3/releases), не Intel-сборка (ошибка «неверная архитектура» / код -86).

### Автообновление

1. Тег `v3.1.18` на GitHub → Actions **Desktop Release**.
2. Установленное приложение ~раз в 30 мин проверяет обновления.
3. macOS: в релизе отдельно **x64** и **arm64** zip/dmg.

Логи: `~/Library/Application Support/spread-system-v3-desktop/logs/` (`backend.log`, `updater.log`).

## Частые проблемы

| Симптом | Что проверить |
|---------|----------------|
| Поток: Проблема | Сохранён ли конфиг; 10–30 с после старта; `market_data_stale_after_seconds` |
| Нет сделок в Paper | Автоторговля; пороги Скальп; мягкие сигналы |
| Backend не стартует (Mac) | Версия DMG под архитектуру CPU |
| P/L странный | После v3.1.18 исправлена цена выхода (bid/ask не перепутаны) |
| Счётчик ≠ таблица | Обновитесь до v3.1.18 — таблица показывает все сделки, REST-синхронизация |
